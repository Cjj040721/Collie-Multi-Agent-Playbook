# 竞品调研笔记(1/3):Herdr —— 终端原生的 agent runtime

> 调研日期:2026-07-31。取证方式:官网(herdr.dev)文档全文 + GitHub API + README。事实均标注来源;「推测」处单独标明。第三方聚合站上流传的 `herdr fanout`、`herdr headless` 等命令在官方 CLI 文档中不存在,疑似编造,本笔记不采信。

## 产品速览

- 定位:"agent multiplexer that lives in your terminal" / "the runtime your coding agents live on"——懂 agent 的 tmux。
- 形态:Rust 单二进制(10–20MB,无依赖),Apache-2.0,完全免费,靠 GitHub Sponsors 全职开发;无账号、无遥测。来源:[README](https://github.com/herdrdev/herdr)
- 活跃度(2026-07-30 GitHub API 实测):22.4k stars / 1.5k forks,仓库 2026-03-27 创建,最新 release v0.7.5(2026-07-21),0.x 阶段但迭代极快(release notes 里大量各家 agent 状态检测修复)。来源:[repo](https://github.com/herdrdev/herdr)
- 结构层级:**workspace(项目容器)→ tab(布局)→ pane(真实 PTY 终端)→ agent(pane 内被识别的前台进程)**。另有 named session = 独立 server 命名空间。来源:[concepts](https://herdr.dev/docs/concepts/)

## 核心机制拆解

**进程模型(官方写明)**:Client/Server 架构,默认即持久化——server 拥有所有 pane 和进程状态,client 是可多开的终端 UI。每个 pane 是真实 PTY 跑真实进程,不是包装过的聊天视图。server 向托管 pane 注入 `HERDR_SOCKET_PATH`、`HERDR_ENV=1`、`HERDR_WORKSPACE_ID/TAB_ID/PANE_ID` 环境变量——**agent 靠环境变量自证"我在 Herdr 里、我能被编排"**。来源:[how-to-work](https://herdr.dev/docs/how-to-work/)、[socket-api](https://herdr.dev/docs/socket-api/)

**会话持久化(官方写明,四档能力递增,是本次调研最精细的设计)**,来源:[session-state](https://herdr.dev/docs/session-state/):

| 场景 | 进程存活 | 布局恢复 | 屏幕内容 | agent 对话 |
|---|---|---|---|---|
| detach/reattach | ✅ 从未停止 | ✅ | ✅ | ✅ |
| server 重启 | ❌ | ✅(session.json 快照) | 仅开了 pane history(默认关,怕存 secrets) | 仅原生 session 恢复 |
| update --handoff(实验性) | ✅ best-effort | ✅ | ✅ | ✅ |

- 关键招:**native agent session restore**(默认开)——integration 上报 agent 原生会话引用(`claude --resume <id>`、`codex resume <id>`、`kimi --session <id>`),server 重启后用 agent 自己的 resume 命令拉起,支持 14 家。借 agent 原力,成本极低。
- live handoff:升级时旧 server 把活 pane 的 PTY 移交给新 server;明确不保证在途 API 请求/订阅流/pane 间消息。

**工作区隔离(官方写明)**:workspace 默认共享 checkout;但 socket API 有 `worktree.list/create/open/remove` 全套——`worktree.create` 建 branch + checkout 并返回新 workspace,`worktree.remove` 永不删分支,snapshot 带 provenance 溯源,有 `worktree.created/opened/removed` 生命周期事件供插件 hook。来源:[socket-api Worktree 段](https://herdr.dev/docs/socket-api/)。推测:worktree 是后期补的能力,深度不如 Orca 的"worktree 即基本单元"。

**远程/relay(官方写明)**:不做自研 relay 协议,三条路径全押 SSH——① 传统 ssh 上去跑 herdr(手机端推荐路径);② `herdr --remote <host>` thin client:本地 UI + SSH 桥接远端 server,能桥接本地剪贴板图片、复用 OpenSSH 配置/ssh-agent、自动检测安装远端二进制;③ direct attach:`herdr agent attach <name>` 整个终端附着到单个 agent(单一写所有权,`--takeover` 抢),另有机器友好的 observe/control NDJSON 流。断线重连 = "SSH 断了再 attach",server 端进程一直在;keepalive 靠 SSH 层配置。来源:[persistence-remote](https://herdr.dev/docs/persistence-remote/)。推测:恢复动作比 Orca 的租约制 relay 手动,但语义简单可靠。

**agent 间消息/编排(官方写明,Herdr 最厚的部分)**:
- 控制面 = NDJSON over 本地 socket(Unix socket / Windows named pipe),`herdr api schema --json` 可导出完整 JSON Schema。三层用法共享同一控制面:agent skill → CLI wrapper → raw socket。来源:[socket-api](https://herdr.dev/docs/socket-api/)
- **agent 驱动 agent 是一等场景**:官方 ship 一个 agent skill(`skills/herdr/SKILL.md`),agent 检测到 `HERDR_ENV=1` 即可分屏、起兄弟 pane 的 helper agent、读输出、`agent wait` 等另一个 agent 完成。来源:[agent-automation](https://herdr.dev/docs/agent-automation/)、[agent-skill](https://herdr.dev/docs/agent-skill/)
- 竞态细节都想到了:`agent prompt <name> --wait` 是原子单次请求(带 5 秒停滞检测);`agent wait` 是 server 端事件驱动且 **pin 住当前 pane 占用者**(agent 退出换人糊弄不掉);事件订阅 `pane.agent_status_changed`/`pane.output_matched`/worktree 生命周期可做 reactive 编排。
- **状态灯双轨制(每 pane 单一权威源)**,来源:[agents](https://herdr.dev/docs/agents/):① lifecycle hooks 自报(装了 integration 时权威,Kimi 等有完整 hook)——自报权威时不跑屏幕检测,避免两个真相源打架;② screen manifest 屏幕检测(fallback)——对 pane 底部缓冲快照跑 TOML 规则,Claude Code/Codex 等故意只用屏幕检测(它们的 hook 覆盖不全,会漏权限审批)。**blocked 宁漏勿错**:只明确匹配到审批/提问/权限 UI 才标 blocked,否则回落 idle。检测 manifest 支持远程热更新。`done = idle + 你还没看过它`(focus 后变 idle),状态向 tab/workspace 逐级 rollup。

## 值得抄的

1. **四档持久化语义表**——尤其"用 agent 自己的 `--resume` 恢复对话",把对话持久化外包给 agent 原力,是最诚实的成本取舍。
2. **环境变量自证机制**(`HERDR_ENV`/`HERDR_PANE_ID`)——pane 内 agent 知道自己能被编排的最小契约。
3. **状态双轨权威 + 单一权威源**(hook 优先、屏幕兜底、永不双跑)+ blocked 保守判定。
4. `agent prompt --wait` 原子化、wait pin 占用者——agent 互操作的竞态都被堵死。
5. `done = idle + unseen` 把通知语义内建进状态机,不需要独立通知队列。
6. thin client 走 SSH 复用而非自研 relay,远端接入信任成本极低。

## 要避开的坑

1. **屏幕检测永远追不上 agent UI 变化**(release notes 里全是误判修复),manifest 热更新是被迫的运营负担——有 hook 的 agent 一定走 hook。
2. alternate screen 的全屏 agent(Claude Code 等)输出不进 host scrollback,`pane read` 读不到历史——读 agent 输出做编排有天花板,官方自己都建议"让 agent 把结果写成文件再读文件"。
3. **没有任务层**:issue/复核/分工全靠插件自建(社区 430+ 插件,manifest 驱动)。
4. Windows 仍 beta 且 remote 缺席;live handoff 不保证在途 API 调用和 pane 间消息。

## 两个差异化洞察在 Herdr 身上差多远

**洞察一(中控 agent 一等公民):原料齐备、角色缺席(介于完全没有与半成品之间)。** agent 驱动 agent 的能力面是三家最完整的(socket API + 官方 skill + 原子 wait + 事件订阅),任何一个装了 skill 的 agent 都能驱动整个 session——但官方文档**没有任何 lead/orchestrator 角色概念**,编排是去中心化能力而非角色,谁当中控由用户自定。缺的不是机制,是"持续在岗、读台账、拆任务、复核产出"的角色定义和配套上下文管理。

**洞察二(分级复核成本结构):完全没有。** 无任务层、无复核状态机、无凭据概念;最接近的只有 `done = 未查看` 的通知语义和社区插件市场里的 "Review diffs beside the agent / Approve from your phone" 类插件。复核这件事在 Herdr 的世界观里不存在。

**一句话结论:Herdr 把"终端里的 agent 进程"这一层做到了极致(持久化四档、状态双轨、socket 编排原语),但它自觉停在进程层——任务、角色、复核全是空白,这正是 Collie 中控洞察的空档所在。**
